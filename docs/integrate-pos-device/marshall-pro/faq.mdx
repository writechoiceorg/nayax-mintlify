## Connecting the Device to Your POS or Simulator

To connect to the device, use the TCP protocol through port 5050. No physical connection to your computer is required.

For your device's Wifi connection setup, see [Configuring Wifi (and IP)](/docs/integrate-pos-device/marshall-pro/faq#configuring-wifi-and-ip) below. For LAN, see [Configuring ETH (and IP)](/docs/integrate-pos-device/marshall-pro/faq#configuring-eth-and-ip).

### Activating the Device

<Steps>
  <Step title="Scan the QR code">
    Scan the QR code displayed on the device's screen using your phone's camera. The following photo shows a VPOSM4S device, but the process is identical for VPOSM5.
    <Frame>
      ![QR code displayed on the device screen for activation](/images/docs/faq/image1.png)
    </Frame>
  </Step>
  <Step title="Complete the landing page">
    You're redirected to a landing page where you enter the required details. After submission, a verification code is sent by email. Enter it on the landing page to complete the device activation.
    <Frame>
      ![Landing page for entering device activation details](/images/docs/faq/image2.png)
    </Frame>
  </Step>
</Steps>

### Getting the Device's Details (Serial Number, IP)

<Steps>
  <Step title="Set the device to Out of Service">
    Disconnect the link to the device and wait 30 seconds.
    <Frame>
      ![Device screen showing Out of Service status](/images/11.png)
    </Frame>
  </Step>
  <Step title="Open Device Info">
    Click five times on the top-right corner of the screen, then select **Device Info**.
    <Frame>
      ![Device menu with the Device Info option highlighted](/images/27-1.png)
    </Frame>
  </Step>
  <Step title="Review the device details">
    Device Info shows the device's serial number, along with its cellular and Ethernet communication details. In this example, the device has an eSIM and is also connected to Wifi.
    <Frame>
      ![Device Info screen showing serial number and connectivity details](/images/28-1.png)
    </Frame>
  </Step>
</Steps>

To return to the device's idle screen for making transactions, click the top-left arrow, then select **Payment App**.

### Configuring Wifi (and IP)

VPOSM over Marshall supports either DHCP or Static IP, depending on how you want the device to work. DHCP is the default.

> **FLAG:** Conflict. This section describes "VPOSM over Marshall," but it's on the Marshall Pro FAQ page. Marshall Pro's own product docs describe it as a distinct TCP/IP protocol from Marshall's SDK. Confirm with the Nayax team whether this sentence is accurate for Marshall Pro devices, or whether it was carried over from Marshall documentation by mistake.

<Steps>
  <Step title="Open the Technician menu">
    Click a few times on the top-left corner of the screen, then select **Technician Menu**.
    <Frame>
      ![Technician Menu opened on the device](/images/29.png)
    </Frame>
  </Step>
  <Step title="Enter the technician code">
    Enter the code (123123 by default), then scroll down to the **Communication** section.
    <Frame>
      ![Technician Menu with the Communication section highlighted](/images/image-1.png)
    </Frame>
  </Step>
  <Step title="Select Wifi">
    Select **Wifi**, then select the relevant network.
    <Frame>
      ![Communication section with the Wifi option](/images/image-6.png)
    </Frame>
  </Step>
  <Step title="Open the network's advanced settings">
    Click the gear icon for the relevant network, then select **Advanced**.
    <Frame>
      ![Network settings with the gear icon highlighted](/images/image-15.png)
    </Frame>
    <Frame>
      ![Advanced network settings screen](/images/image-16.png)
    </Frame>
  </Step>
  <Step title="Set a static IP">
    Scroll down to **IP Settings**, which is set to DHCP by default, and switch it to **Static**. Fill in the IP details.
    <Frame>
      ![IP settings showing the option to switch from DHCP to Static](/images/image-17.png)
    </Frame>
  </Step>
</Steps>

## Triggering the Apps Update Process (Accessing the CasHub App)

Nayax Fuel initiates firmware updates from a separate platform called CasHub. The update process updates each relevant application individually, rather than as a single package, in two stages: download and update.

Once the download finishes, Nayax Fuel's support team sends the device a request to start the update for the desired applications. You can also trigger the update yourself. Turn on the device and use one of the following options:

1. Leave the device powered on overnight. It resets automatically at approximately 3-4 AM, at which point the device collects and starts the updates.
2. Manually access the CasHub app to trigger the download and installation of the updates.

To trigger the update manually, follow these steps:

<Steps>
  <Step title="Set the device to Out of Service">
    Disconnect the link to the device and wait 30 seconds.
    <Frame>
      ![Device screen showing Out of Service status](/images/11.png)
    </Frame>
  </Step>
  <Step title="Open the Technician menu">
    Click five times on the top-right corner of the screen, then select **Technician Menu**. Enter the password 123123.
    <Frame>
      ![Technician Menu password prompt](/images/12.png)
    </Frame>
  </Step>
  <Step title="Open Dev Mode">
    Scroll down to **Dev Mode** and enter the password 321321.
    <Frame>
      ![Technician Menu with the Dev Mode option](/images/13.png)
    </Frame>
  </Step>
  <Step title="Return to Android settings">
    Select **Wifi**, then select the back arrow to return to the Android settings.
    <Frame>
      ![Wifi settings within Dev Mode](/images/14.png)
    </Frame>
    <Frame>
      ![Android settings screen](/images/15.png)
    </Frame>
  </Step>
  <Step title="Open Apps & Notifications">
    Go to **Apps & Notifications**, then select **See All Apps** (in this example, the device has 24 apps).
    <Frame>
      ![Android settings with the Apps and Notifications option](/images/16.png)
    </Frame>
    <Frame>
      ![Full list of apps on the device](/images/17.png)
    </Frame>
  </Step>
  <Step title="Open the CasHub app">
    Select the CasHub app and open it.
    <Frame>
      ![App list with CasHub selected](/images/18.png)
    </Frame>
    <Frame>
      ![CasHub app info screen](/images/19.png)
    </Frame>
  </Step>
  <Step title="Connect and start the update">
    Click **Status**, then select the three dots in the top-right corner and choose **Connect**.
    <Frame>
      ![CasHub app Status screen](/images/20.png)
    </Frame>
    <Frame>
      ![CasHub app menu with the Connect option](/images/21.png)
    </Frame>
  </Step>
  <Step title="Wait for the connection">
    The screen displays "Connecting..." both at the top and in the table below. If this persists for more than one minute, the process has likely stalled.
    <Frame>
      ![CasHub app showing the Connecting status](/images/22.png)
    </Frame>
  </Step>
  <Step title="Download and install the updates">
    The download and update of the apps begins.
    <Frame>
      ![CasHub app downloading updates](/images/23.png)
    </Frame>
  </Step>
  <Step title="Confirm the update finished">
    Once all apps finish downloading and updating, a "Finished" line appears.
    <Frame>
      ![CasHub app showing the Finished status](/images/24.png)
    </Frame>
  </Step>
</Steps>

Some apps can only be downloaded, not installed, at this stage, since the device can't update applications that are currently running. This applies to:

- Nayax Launcher
- Update Service
- VPOS Service

For these, reboot the device afterward. The apps update during the device's power-up sequence, and a "Castles: Updating (application)" notification appears for about one minute.

<Note>
  **"vpos_media keeps stopping" error**

  This error happens because the Vendapp crashes, which isn't relevant to your setup. This can occur if the Vendapp is set as the default application:

  <Frame>
    ![Error notification showing vpos_media has stopped](/images/25-1.png)
  </Frame>

  or if the relevant parameter value is empty or missing (in either case, the device defaults to Vendapp). If the parameter is correctly set to Fuel and you still get this error, update the Vendapp.

  <Frame>
    ![Parameter setting correctly configured to Fuel](/images/26.png)
  </Frame>
</Note>
