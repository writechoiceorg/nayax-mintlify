Use this tool to check a Marshall SDK or firmware log against known-good reference traces without reviewing it line by line. You can give it:

- A log file (`.txt` or `.log`)
- An Excel certification workbook, where each sheet is treated as one test
- Log text pasted directly, on the **Paste log text** tab

The tool runs it through the same nine checkpoints Nayax uses when reviewing your certification tests: boot handshake, reader state, vend and authorization flow, and session close. The [Checkpoints & Scenario Tags](/docs/integrate-pos-device/marshall/log-analysis/log-trace-comparator-guide) page documents each one.

<Note>
Everything runs locally in your browser. Log files never leave your machine, except for the "Learn more" links, which open Nayax's documentation.
</Note>

## Setting the timing threshold

The timing anomaly threshold sets how large a gap between two consecutive events in the log the tool flags as unusual. Gaps appear in the log as `+Xms`. The default is 15000 milliseconds, which is 15 seconds.

Raise the threshold when a test includes an intentional long wait, such as a 24-hour idle test, a session timeout, or a stress test. For a one-hour wait, set it to 3600000. If you leave the default in place, the tool reports a failure on timing that is really the test working as designed.

## Reading the results

Each log or sheet gets a verdict badge:

- <Badge color="green">ALL CHECKS PASSED</Badge>: every checkpoint passed, no action needed.
- <Badge color="orange">REVIEW RECOMMENDED</Badge>: at least one checkpoint raised a warning worth a manual look. Not necessarily a bug.
- <Badge color="red">FAILED CHECKS FOUND</Badge>: at least one checkpoint failed outright and needs attention.

Below the badge, a trace strip shows one dot per checkpoint, in the same colors:

- <Badge color="green">Green</Badge>: pass
- <Badge color="orange">Amber</Badge>: warning
- <Badge color="red">Red</Badge>: fail
- <Badge color="gray" variant="outline">Hollow gray</Badge>: not applicable to that log

For any checkpoint that isn't green, a "Suggested fix" box explains the likely cause and links to the relevant documentation. An evidence line shows the exact log line the checkpoint was based on.
