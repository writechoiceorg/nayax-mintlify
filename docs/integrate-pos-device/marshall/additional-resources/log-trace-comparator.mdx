Use this tool to check a Marshall SDK or firmware log against known-good reference traces without reviewing it line by line. Drop in either of the following:

- A log file (`.txt` or `.log`)
- An Excel certification workbook, where each sheet is treated as one test

The tool runs it through the same checkpoints Nayax uses when reviewing your certification tests: boot handshake, reader state, vend and authorization flow, and session close.

<Note>
Everything runs locally in your browser. Log files never leave your machine, except for the "Learn more" links, which open Nayax's documentation.
</Note>

## Reading the results

Each log or sheet gets a verdict badge:

- **ALL CHECKS PASSED** (green): every checkpoint passed, no action needed.
- **REVIEW RECOMMENDED** (amber): at least one checkpoint raised a warning worth a manual look. Not necessarily a bug.
- **FAILED CHECKS FOUND** (red): at least one checkpoint failed outright and needs attention.

Below the badge, a trace strip shows one dot per checkpoint, in order: green for pass, amber for warning, red for fail, hollow gray for not applicable to that log. For any checkpoint that isn't green, a "Suggested fix" box explains the likely cause and links to the relevant documentation page, and an evidence line shows the exact log line the checkpoint was based on.

<Tip>
If a test includes an intentional long wait, such as a 24-hour idle test, a session timeout, or a stress test, raise the timing anomaly threshold before running it. Otherwise the tool reports a FAIL on timing that's actually the test working as designed.
</Tip>
